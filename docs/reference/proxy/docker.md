# Docker Mode

The proxy always runs via `docker compose` against `~/.codefreedom/proxy/docker-compose.yaml`. The stack brings up two services on a private `codefreedom` bridge network:

- `litellm` — the proxy itself, in the self-hosted `codefreedom:litellm-latest` image (with the WebSearch count display patch baked in)
- `web-bridge` — a FastAPI SearXNG-shaped sidecar that talks to the Camoufox MCP (see [Web Search Interception](websearch-interception.md))

Docker is therefore a hard prerequisite for the proxy — there is no native Python mode.

## Compose Stack

The `docker-compose.yaml` (generated by `codefreedom proxy init`) runs the two services:

```yaml
services:
  litellm:
    image: docker.io/nilayparikh/codefreedom:litellm-latest
    container_name: litellm-codefreedom
    profiles:
      - litellm
      - all
    ports:
      - "0.0.0.0:4000:4000"
    volumes:
      - ./config:/app/litellm-config:ro
    extra_hosts:
      - host.docker.internal:host-gateway
    networks:
      - codefreedom

  web-bridge:
    image: docker.io/nilayparikh/codefreedom:web-bridge
    container_name: codefreedom-web-bridge
    profiles:
      - litellm
      - all
    extra_hosts:
      - host.docker.internal:host-gateway
    networks:
      - codefreedom
    # No ports: -- the bridge is only reachable on the codefreedom network
    # at http://web-bridge:8500.
```

## Key Details

**Config mount** — `./config:/app/litellm-config:ro` mounts `~/.codefreedom/proxy/config/` into the container read-only. The container reads `config.yaml` and provider YAMLs from this path.

**`host.docker.internal`** — The `extra_hosts` entry maps `host.docker.internal` to the host machine. This lets the proxy reach local inference servers (e.g., `http://host.docker.internal:8000/v1`) running on your machine. Without this, the container can't see host ports.

**Patch baked in** — The WebSearch count display patch is applied during the image build (see `docker/litellm/patch_websearch_count.py` and the `RUN python patch_websearch_count.py` step in `Dockerfile.LiteLLM`). No entrypoint wrapper, no volume mount, no runtime mutation. Rebuild the image to pick up LiteLLM or patch changes — not on every container start.

**Environment merging** — Docker Compose interpolates `${VAR}` from `.env.proxy` (lowest priority). System environment variables override `.env.proxy` values. `.env.proxy.secrets` is loaded at runtime by the CodeFreedom CLI.

**Network** — The `codefreedom` bridge network isolates the proxy. Other CodeFreedom containers (sandbox, tools) can join this network to reach the proxy at `http://litellm-codefreedom:4000`.

**Image version control** — Override `LITELLM_IMAGE` in `.env.proxy` to pin a specific version (e.g. `codefreedom:litellm-v0.1.0`) or use a locally-built image. The default `litellm-latest` tracks the latest published version.

## Building the LiteLLM Image Locally

To build a custom LiteLLM image (for example, after bumping the pinned version in `docker/litellm/requirements.txt`):

```bash
docker build \
  --build-arg IMAGE_VERSION=0.1.1 \
  -t codefreedom:litellm-local \
  -f docker/litellm/Dockerfile.LiteLLM \
  docker/litellm/
```

Then point the proxy at it:

```bash
echo "LITELLM_IMAGE=codefreedom:litellm-local" >> ~/.codefreedom/.env.proxy
codefreedom proxy start
```

## Direct Docker Commands

If you want to bypass `codefreedom proxy start` for any reason:

```bash
# Start
docker compose -f ~/.codefreedom/proxy/docker-compose.yaml --profile litellm up -d

# Stop
docker compose -f ~/.codefreedom/proxy/docker-compose.yaml --profile litellm down

# Logs
docker compose -f ~/.codefreedom/proxy/docker-compose.yaml --profile litellm logs -f litellm
```

For more, see [LiteLLM Docker](https://docs.litellm.ai/docs/proxy/docker).
